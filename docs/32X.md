# Sega 32X Support Plan

This document tracks mdSharp's 32X implementation path. The current build recognizes 32X cartridges, attaches the 32X device shell, boots the MARS user header into SDRAM, runs both SH-2s in the frame loop, renders packed-pixel/direct-color/run-length framebuffer output, and reaches visible output in several SDK samples and retail titles. The implementation is still preliminary, but it is now useful for compatibility triage rather than only bring-up diagnostics.

## Hardware Shape

The 32X is an add-on in the Mega Drive cartridge path, not a normal cartridge mapper. A 32X game still starts from the Mega Drive 68000 side, then enables the 32X block and coordinates with the add-on.

Major pieces:

- Two Hitachi SH-2 CPUs, fixed as master and slave.
- 256 KiB SDRAM shared by the SH-2 side.
- Two 128 KiB framebuffers used as draw/display buffers.
- 32X VDP with direct color, packed pixel, and run-length modes.
- 256-entry 32X color palette.
- Stereo PWM audio mixed with the base PSG/YM2612 output.
- 68000-visible system registers, VDP registers, palette, communication ports, FIFO, DREQ, and PWM registers.
- Cartridge ROM visible from both 68000 and SH-2 sides with access priority/arbitration.

Important 68000 address anchors:

| Area | Address |
| --- | --- |
| 32X frame buffer | `$840000` |
| Overwrite image | `$860000` |
| Cartridge fixed window | `$880000` |
| Cartridge banked window | `$900000` |
| Super 32X ID | `$A130EC` |
| System registers | `$A15100` |
| VDP registers | `$A15180` |

## Implementation Phases

1. Cartridge recognition and diagnostics.

   Done for the first slice: `.32x` files are included in desktop/CLI ROM selection, `CartridgeDiagnostics.Requires32X` flags 32X cartridges, and `--cart-info` / `--cart-scan` expose the requirement.

2. 32X shell device.

   Partly done: `ThirtyTwoXDevice` now attaches to 32X cartridges and exposes deterministic reset defaults, SDRAM, framebuffers, palette memory, system/VDP register storage, the Super 32X `MARS` ID, framebuffer switching state, PWM pulse-width FIFOs, and master/slave SH-2 instances. The adapter-control register now tracks adapter enable, SH-2 reset enable/release, and VDP access authorization. The shell also parses the MARS user header, copies the initial SH-2 program to SDRAM, and initializes master/slave entrypoints and VBRs. DREQ CPU-write mode, FIFO status, SH-2 DMA channel-0 FIFO transfers, and coarse ROM-to-VRAM DMA snooping from the Genesis VDP DMA path are implemented. DREQ snooping now lets SH-2 DMA drain a full FIFO before accepting the next VDP DMA word, avoiding dropped burst data in the common producer/consumer path. DREQ FIFO DMA is gated by SH-2 module/external request mode and `DRCR=00`, while ordinary memory DMA remains immediate for now. It still needs exact interrupt routing, FIFO/DREQ cycle timing, and bus-arbitration behavior.

3. 68000 bus integration.

   Partly done: `GenesisBus` now attaches the 32X shell for 32X cartridges, exposes the Super 32X `MARS` ID at `$A130EC`, routes 68000 system registers and communication ports, VDP registers, palette access, the `$840000` framebuffer window, the `$880000` fixed cartridge window, and the `$900000` banked cartridge window, and saves/restores shell state. The 68000 bootstrap now sees the adapter-ready/reset-enable bit needed to pass the standard MARS wait loop. If a local 32X 68000 BIOS is supplied, low 32X vector/monitor reads can come from that file instead of mdSharp's synthetic vector shim. Remaining work includes full built-in 32X boot ROM behavior, overwrite image edge cases, bus-arbitration timing, and exact access authorization timing.

4. SH-2 CPU core.

   Started: `Sh2Cpu` now has reset/state capture, unsupported-opcode trapping, master/slave instances in `ThirtyTwoXDevice`, and a growing integer/data-move/branch instruction slice. It includes common PC-relative literal loads, byte/word/long loads and stores, predecrement/postincrement forms, indexed `@(R0,Rn)` moves, register logical ops, immediate logical ops, compares, shifts/rotates, multiplies, branch delay-slot execution, branch-register forms, and selected control register moves. The SH-2 side can fetch from cached/cache-through cartridge windows, access SDRAM, read/write communication ports, and touch 32X register/palette/framebuffer ranges through its own bus. VRES/V/H/CMD/PWM interrupt clear registers now clear only the issuing SH-2 latch, preserving the peer CPU's pending latch. SH-2 DMA completion now sets TE, clears DE, requests VCRDMA interrupts when CHCR.IE and IPRA priority are enabled, and clears the pending interrupt when software clears TE. Next steps are fuller exception/interrupt coverage, DMA/FIFO timing, and enough opcode coverage for the remaining short-sweep failures.

5. Boot ROM and startup path.

   Partly done: the MARS user header at `$3C0` is parsed, including version, initial ROM source, SDRAM destination/size, master/slave start addresses, and master/slave VBRs. The emulator does not include copyrighted BIOS ROMs. For local testing, the app and desktop front end will use a user-provided 32X 68000 BIOS from `MDSHARP_32X_M68K_BIOS`, `32X_G_BIOS.BIN`, or `32X_M68K_BIOS.BIN` in the app/current directory. Master/slave SH-2 BIOS loading and the full security handshake remain future work.

6. SH-2 bus and synchronization.

   Partly done: both SH-2s run once per scanline using a coarse clock-derived budget. VRES reset-button interrupts are latched and cleared per SH-2, but exact reset-button timing still needs hardware validation. Remaining work is precise synchronization, bus priority, exact CMD/V/H/PWM interrupt timing, FIFO/DREQ cycle timing, and save-state coverage for any added timing cursors.

7. 32X VDP.

   Partly done: the compositor can overlay packed-pixel, direct-color, and run-length framebuffers over the Mega Drive frame and uses the 32X line table. Run-length mode treats palette index 0 as drawable black and decodes `0x0000` as a valid one-pixel black span, matching SDK sample behavior. 32X compositing now compares the 32X front/back and per-palette through bits against the final Mega Drive opaque-pixel mask, matching the add-on's single MD-screen priority model and fixing cases such as Doom's Genesis-rendered HUD/status bar. Framebuffer swaps are currently vblank-gated for correctness. SH-2 framebuffer accesses now pay a coarse busy wait while a non-blank framebuffer swap is pending instead of dropping writes; the 68000-side framebuffer window remains gated during that pending swap. FBCR now reports separate VBlank, HBlank, palette-access, framebuffer-denied, and framebuffer-select bits, and SH-2 palette accesses pay a coarse wait while palette access is not approved. A diagnostic fallback can display a populated draw buffer when the display buffer and mode registers have not yet been switched by the incomplete interrupt/status model; this remains useful for some startup paths but should be replaced with exact VDP status/timing. Remaining work includes exact screen shift, through-bit edge cases, fill timing, palette access windows, and framebuffer switching edge cases.

8. PWM audio.

   Partly done: PWM pulse-width writes are captured and mixed into `MegaDrive` stereo audio after PSG/YM2612 generation. FIFO full handling now rejects new samples instead of dropping queued samples, mono writes are blocked when either stereo hardware FIFO is full, and rendered PWM output respects the control register's left/right routing bits. The PWM timer now treats `TM=0` as the longest 4-bit interval and resets internal counters when timing registers are rewritten. Remaining work includes cycle-exact interrupt cadence, DREQ/RTP behavior, analog filtering, and broader retail-game validation.

9. Save states and diagnostics.

   Extend save states, input movies, compatibility dashboards, traces, and performance counters for SH-2s, 32X registers, framebuffers, palette, PWM state, and synchronization state.

10. Compatibility ladder.

   Start with Mars check programs and SDK samples, then low-complexity retail titles such as Space Harrier and After Burner, then Doom/Star Wars Arcade/Knuckles Chaotix, then Virtua Racing Deluxe and higher-stress 3D titles.

## Local Test Strategy

Use the `32x_roms` folder as a local-only compatibility source. It should stay ignored by git like the retail Genesis ROM collection.

Suggested first commands:

```powershell
dotnet run --project src\MdSharp.App\MdSharp.App.csproj -c Release -- --cart-scan 32x_roms render-output\32x-cart-scan.csv
dotnet run --project src\MdSharp.App\MdSharp.App.csproj -c Release -- --cart-info "32x_roms\...\Mars Check Program (...).32x"
dotnet run --project src\MdSharp.App\MdSharp.App.csproj -c Release -- --32x-sh2-trace "32x_roms\...\Mars Check Program (...).32x" 10000 master
```

Current smoke command:

```powershell
dotnet run --project src\MdSharp.App\MdSharp.App.csproj -c Release -- --compat 32x_roms render-output\32x-compat-pass4 30 200000 --screenshots
```

Current status:

- A 120-frame SDK sweep shows visible output for Gnu Sierra, Pharaoh, Runlength Mode Test, and Texture Test. Runlength Mode Test renders the expected faceted Sonic model, and Texture Test renders the red/green checker triangle.
- The first retail batch reaches visible output in After Burner Complete, Amazing Spider-Man, BC Racers, Chaotix, Cyber Brawl, and Doom. Blackthorne is still at a dark/early-logo state in the short sweep, and Brutal Unleashed currently depends on draw-buffer fallback.
- SH-2 linked-list/rechain fast paths are disabled by default because they corrupted the Mars runlength sample. They can be enabled for experiments with `MDSHARP_ENABLE_SH2_LIST_FASTPATHS=1`, but correctness should be validated against interpreter traces before making them default again.

The next milestone is exact 32X interrupt/status/framebuffer switching and priority behavior so retail games can progress deeper without diagnostic fallback, followed by a corrected high-performance version of the linked-list/rechain accelerators. Current SH-2 framebuffer and palette timing uses coarse busy waits; this preserves real software behavior better than dropping writes, but still needs cycle-accurate bus ownership and status timing.
